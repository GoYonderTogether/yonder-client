# @yonder/desktop（Tauri 2 壳）

Thin native shell around the web build. One window, one page: `apps/web/dist` says **Yonder** and
the version. No plugins, no tray, no background process, no second set of system notifications.

## Identity

|                          | value                |
| ------------------------ | -------------------- |
| productName              | `Yonder`             |
| desktop identifier       | `dev.yonder.desktop` |
| iOS / Android identifier | `net.yonderbot.app`  |

The iOS provisioning profile and the Android keystore are tied to these identifiers. **Do not
change them** — signed builds would stop matching.

## Build

```sh
npm run build -w @yonder/web     # the shell bundles apps/web/dist, build it first
cd apps/desktop && npm install
npm run build                    # tauri build
```

`bundle.targets` keeps `dmg`, `nsis`, `deb`, `appimage`; platforms the bundler cannot build on are
skipped. `bundle.icon` points at the PNG sizes, `icons/icon.ico` (Windows) and
`icons/icon.icns` (macOS).

Release builds inject the version instead of reading it from the repo:
`tauri build --config '{"version":"<version>"}'`, so `package.json` / `tauri.conf.json` /
`Cargo.toml` only need to stay at a consistent placeholder. Artifact names follow Tauri 2:

| platform              | artifact                         |
| --------------------- | -------------------------------- |
| macOS (Apple Silicon) | `Yonder_<version>_aarch64.dmg`   |
| Windows x64           | `Yonder_<version>_x64-setup.exe` |

`desktop-release.yml` signs and notarizes the macOS app and dmg with Developer ID when the
certificate secrets are present, or warns and uses ad-hoc signing when they are absent. It builds
the Windows nsis installer unsigned and uploads both to the GitHub Release and OSS `desktop/<version>/`.

## iOS / Android

`src-tauri/gen/` is generated by `tauri ios init` / `tauri android init` and is not committed.
Both generated projects need a small set of settings re-applied afterwards, because `init`
regenerates them from scratch:

```sh
npx tauri ios init --ci      && node prepare-ios.mjs      # icons without alpha, signing team/profile
npx tauri android init --ci  && node prepare-android.mjs  # signing, Gradle mirrors, keyboard resize
```

- `prepare-ios.mjs` flattens the 1024 icon (App Store rejects alpha, error 90717), writes
  `DEVELOPMENT_TEAM` / `CODE_SIGN_STYLE=Manual` / `PROVISIONING_PROFILE_SPECIFIER` and switches
  `CODE_SIGN_IDENTITY` to `iPhone Distribution`. Team and profile name come from
  `IOS_TEAM_ID` / `IOS_PROFILE_NAME` (CI passes the secrets). It also marks standard TLS as exempt
  from export compliance documentation in the generated app plist.
- `prepare-android.mjs` writes `keystore.properties` and wires the release `signingConfig`, adds
  AliCloud Gradle mirrors (dl.google.com is unreachable from mainland networks), turns off the AGP
  SDK auto-download probe, and applies `adjustResize` plus the IME inset bridge in `MainActivity`.
  Without a keystore the release build stays unsigned and still builds.
- `versionCode` is `YYMMDDNN` from the release version, injected by `android-release.yml` through
  `--config`; the static value in `tauri.android.conf.json` is only a local-debug placeholder.

## Signing material (CI secrets)

| secret                                                                                 | used by                              |
| -------------------------------------------------------------------------------------- | ------------------------------------ |
| `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`            | android-release.yml                  |
| `IOS_DISTRIBUTION_CERT_P12_BASE64`, `IOS_DISTRIBUTION_CERT_PASSWORD`                   | ios-release.yml                      |
| `IOS_PROVISIONING_PROFILE_BASE64`, `IOS_TEAM_ID`                                       | ios-release.yml                      |
| `MACOS_CERTIFICATE_P12_BASE64`, `MACOS_CERTIFICATE_PASSWORD`, `MACOS_SIGNING_IDENTITY` | desktop-release.yml                  |
| `ASC_API_KEY_ID`, `ASC_API_ISSUER_ID`, `ASC_API_PRIVATE_KEY_BASE64`                    | ios-release.yml, desktop-release.yml |

Signing material is restored into the runner's temp directory and deleted afterwards.

## Not verified locally

The macOS app was built and launched on the development machine (unsigned / ad-hoc). iOS,
Android and Windows builds were **not** run locally — no Android SDK/NDK, no signing material, no
Windows runner. CI owns those builds.

## 安装到真机调试

真机跑的是**开发构建**：Xcode 自动管理签名，用 `Apple Development` 证书和
`iOS Team Provisioning Profile: net.yonderbot.app`（profile 里必须有这台机器的 UDID）。
`bundle id` 仍是 `net.yonderbot.app`，与 TestFlight 分发共用同一个 App ID；真机调试不经过
`ios-release.yml`，也不碰分发证书和 App Store profile。

前置条件（本机一次性）：

- 手机上已打开 **开发者模式**（设置 → 隐私与安全性 → 开发者模式），并已信任这台 Mac。
- Xcode → Settings → Accounts 里登录 Apple ID，团队 `D4UZU32UN9` 勾选 Automatically manage signing。
  首次给新设备签开发 profile 需要这个会话。
- 命令行 `cargo` 必须来自 rustup 的 1.99.0 工具链：Homebrew 的 `cargo` 没有 iOS std，
  编译会报 `can't find crate for 'core'`。不必改全局 PATH，只在命令前加一次。

```sh
cd apps/desktop
npm ci && cd ../.. && npm run build                   # 前端产物 apps/web/dist 先出
cd apps/desktop
npx tauri ios init --ci
IOS_SIGNING_STYLE=development node prepare-ios.mjs   # 图标去 alpha + 自动开发签名

export PATH="$HOME/.rustup/toolchains/1.99.0-aarch64-apple-darwin/bin:$PATH"
npx tauri ios build --debug --target aarch64 --export-method debugging
```

产物是 `src-tauri/gen/apple/build/arm64/Yonder.ipa`。装到手机并启动：

```sh
UDID=$(xcrun devicectl list devices | awk '/physical/' | grep -oE '[0-9A-F]{8}-[0-9A-F]{16}' | head -1)
xcrun devicectl device install app --device "$UDID" \
  src-tauri/gen/apple/build/arm64/Yonder.ipa
xcrun devicectl device process launch --device "$UDID" net.yonderbot.app
xcrun devicectl device capture screenshot --device "$UDID" --destination /tmp/yonder.png
```

三点实操结论：

- `IOS_SIGNING_STYLE=development` 只是把生成的工程改成 `CODE_SIGN_STYLE = Automatic` +
  `Apple Development` 并且**不写** `PROVISIONING_PROFILE_SPECIFIER`，让 Xcode 自己挑带本机
  UDID 的开发 profile。不设这个变量时 `prepare-ios.mjs` 行为不变（Manual + 分发证书 +
  `Yonder App Store`），CI 走的就是那条路。
- 不要直接用 `xcodebuild` 绕过 `tauri ios build`：生成的工程里 `Build Rust Code` 阶段要读
  `tauri ios dev` / `tauri ios build` 写下的 `.tauri/cli-options-server.json`，单独跑
  `xcodebuild` 会报 `the tauri ios dev or tauri ios build command must be running`。
- 手机锁屏时 `devicectl ... process launch` 会被 SpringBoard 拒绝
  （`FBSOpenApplicationServiceErrorDomain error 7, Locked`），安装不受影响。先解锁手机再
  launch；`xcrun devicectl device info lockState` 只能看状态，不能代替解锁。解锁后重试即可，
  不需要重装。

签名走 Xcode 自动管理时，本机已经存在覆盖这台手机 UDID 的开发 profile，`tauri ios build` 全程
没有要求登录；只在 profile 过期或换新设备时才需要 Xcode → Settings → Accounts 里那个已登录的
Apple ID 会话（那时可在 Xcode 里手动打开工程让它重新签发一次）。

实测记录（iPhone 17 Pro / iOS 27.2 / Xcode 27.2）：`devicectl install` 返回 `App installed`，
`devicectl process launch` 返回 `Launched application with net.yonderbot.app bundle
identifier`，随即 `devicectl device info processes` 能看到 `Yonder.app/Yonder`，PID 在 30 秒后
不变；两次 `devicectl device capture screenshot`（间隔约 1 分钟）都拍到首页：**Yonder** /
`version 0.3.26111302` / `no server here (offline build)`。
