# Yonder 客户端架构

本文件描述公开客户端仓库**当前代码**的形状和强制规则；代码变了就改这里。2026-11-18 按 main 核对过一次。

- 产品原则和设计稿由维护者单独管理；本文记录公开客户端的实现与分层约束。

## 两个仓库

| 仓库                                     | 内容                                                                             |
| ---------------------------------------- | -------------------------------------------------------------------------------- |
| `yonder-client`（本仓库，公开，GPL-3.0） | Web、macOS、Windows、iOS、Android 壳，微信小程序，协议类型，API 调用层，全部界面 |
| `yonder`（私有）                         | 云端 API、账号、聊天、额度、模型适配与计费、技能正文、数据库、部署               |

本仓库不放生产密钥、数据库地址、模型价格数值、平台供应商的地址或类别。
`packages/protocol` 和 `packages/api-client` 在两个仓库各有一份，必须保持一致，**以本仓库为准**；
改协议时两边同时改。默认服务端是 `https://yonder.zethai.cn`，自建只在构建时用 `VITE_API_BASE`。

## 分层

```
apps/web            装配：providers、路由、页面、输入框、预览、本机能力桥
  packages/ui/features/{auth, me, members, landing, legal, meetings}
  packages/ui/data          TanStack Query、实时连接、本地存储、偏好
  packages/ui/shell         三层导航、布局模式、手势
  packages/ui/components    原子组件
  packages/ui/tokens        设计变量（packages/ui/i18n 与它并列）
  packages/ui/auth-presentation   登录页表现层，Web 和小程序共用
  packages/ui/chat-presentation   聊天/附件/输入区表现与正文解析，Web 和小程序共用
  packages/ui/chat-model          无 React/CSS 的消息合并、连续发送者分组规则

packages/api-client ─▶ packages/protocol（不依赖任何包）
```

- 上层只能依赖下层；feature 之间互不依赖。每个包能依赖谁写在
  `tools/check-dependency-direction.mjs` 的 `LAYERS` 表里，新包必须先登记。
- 包只能从入口导入（`tools/check-entry-imports.mjs`）。
- 单文件 300 行警告、500 行失败（`tools/check-file-length.mjs`）。
- 文案必须同时有 `zh-CN` 和 `en`；颜色、尺寸、圆角只用 tokens；图标用 `lucide-react`。
- `ui/data` 与小程序消息状态都引用 `chat-model` 的纯规则；`ui/components` 与小程序头像也复用其中的首字、稳定配色和 BotFace 路径数据。数据层不为合并消息导入展示 CSS 或另一版本的 React。`chat-presentation` 兼容 React 18/19，DOM 与 Taro 分别提供元素和原生事件适配。

| feature            | 内容                                                                                                              |
| ------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `auth`             | 登录、找回密码                                                                                                    |
| `me`               | 「我」的各个分区：账号与注销、隐私入口、Bot、额度与用量、模型、技能、设备、连接器、邀请、通用、关于；额度不足横幅 |
| `members`          | Bot 表单（新建和修改共用）、Bot 列表和详情、成员资料（真人和 Bot 同一套）、群资料和群管理、隐私三开关             |
| `meetings`         | 会议录音胶囊                                                                                                      |
| `landing`、`legal` | 落地页、协议和隐私                                                                                                |

- 消息气泡不展示工具活动摘要；Web/桌面与小程序只从该消息的 `run.activity` 提取真实来源，按需显示独立“来源”入口，无来源不渲染。后端运行记录与其他卡片不受影响，小程序来源链接沿用点击复制方式。

## 应用和壳

| 目录                       | 内容                                                                                                                                                                                                                         |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/web`                 | 唯一的页面实现。`src/app/` 是外框、弹层和输入框（草稿、补全、语音、录音、附件、拖放），`src/pages/` 是各页面，`src/preview/` 是 PDF、docx、图片预览，`src/lib/` 是平台和本机能力的适配，`src/updates/` 是桌面和 Android 更新 |
| `apps/desktop`             | Tauri 2 壳，同一份 `apps/web` 构建产物。`src-tauri/` 里有本机文件连接器（`local_files*.rs`）、联系人独立窗口、Android 更新；`tauri.ios.conf.json` / `tauri.android.conf.json` 是手机壳                                       |
| `apps/miniprogram`         | Taro 小程序，独立依赖和 lockfile，不在 npm workspaces 里；登录复用 `auth-presentation`，聊天复用 `chat-presentation` 与 `chat-model`，键盘/滚动/文件与预览由宿主适配                                                         |
| `plugins/meeting-recorder` | 会议录音 Tauri 插件（Rust 桌面采集、iOS、Android），4 秒分段 WAV、异常恢复；桌面原生持久上传队列不依赖 WebView，手机在 WebView 可运行时自动提交；界面在 `features/meetings`                                                  |

## 界面模型

- 手机标签依次为主 Bot、消息、任务、记忆，主 Bot 直接打开原有主会话。标签使用 Bot 全名或主人选中的昵称。手机主 Bot 页左上角的设置图标进入账号设置，点击中间的 Bot 头像进入 Bot 详情。桌面竖栏的账号头像、消息、任务和记忆沿同一中轴排列。手机列表的账号头像和桌面竖栏的账号头像、底部设置按钮打开同一分组设置（`/me/:section`）。桌面宽窗（1024 CSS px 起）使用居中设置弹窗，点击外侧可关闭。桌面窄窗和手机使用从左侧滑入的整页设置，逐级返回原页面。
- 「我的 Bot」从 `/me/bots` 进入列表，单个 Bot 的概览、基本资料和对外人格各有页面。账号级的接待 Bot、共用对外资料和待审核草稿在 `/me/reception`。从 Bot 详情进入消息渠道时，`/me/channels?bot=…` 预选该 Bot，返回时回到原详情。连接设置和外部会话分别占一页，账号设置中的外部会话路径是 `/me/channels/external?bot=…`。三个分区沿用设置外壳，宽窗并列目录和内容，窄窗逐页进入。
- 层级从下到上：列表、内容（detail）、右侧栏（`ui/shell` 的 `SideLayers`，由 `AppShell` 的 `side` 统一管理）、弹窗（`Overlay`）。返回、Esc、滑动退出走同一个出口，按这个顺序一层层退：先退右侧栏里叠上去的页，再关右侧栏，再回到列表。手机和电脑是同一套顺序。
- 群聊和普通私聊从顶栏右侧「聊天设置」进入群资料、自己的 Bot 详情或对方的名片。手机主 Bot 页的入口集中在中间头像。Bot 详情与「我的 Bot」共用概览、基本资料和对外人格。直聊 Bot 侧栏为同一会话地址记录浏览器历史，浏览器返回逐层退出。群资料与名片的侧栏子页通过 `useSidePanel().push` 入栈。桌面右上角关闭整栏，也可点栏外空白处关闭。移动端从右侧滑入覆盖聊天，左上角用返回箭头回到上一级。切换会话、标签或页面时右侧栏关闭。
- 真人私聊和群聊的顶栏左对齐显示名称，消息保留左右头像，群聊还显示发言者名字。Bot 私聊在聊天区上方居中显示头像，头像下方只占一行。空闲显示名字，运行时显示本会话的当前状态，超长用省略号。只有双方参与时省去消息头像。
- 手机主 Bot 页紧贴顶部安全区显示 Bot 头像与单行文字。账号设置用左上角圆形描边的悬浮齿轮进入。网页与原生 App 在屏幕顶边使用渐隐，头像、单行文字和齿轮周围使用局部磨砂。滚动起点让第一条消息在头像区下方完整显示，向上滚动时消息可以从局部磨砂后方经过。
- 群资料在群名左侧显示成员组合头像，按权限在页面底部显示「解散群聊」或「退出群聊」。「Bot 设置」是群资料的子页，管理本群的 Bot 回复付费方式。添加成员在桌面是居中弹窗，在手机进入侧栏栈的子页。选人默认可浏览最近聊过的可添加联系人和全部可添加联系人，输入关键词可以筛选。
- 确认、填写类弹窗（确认删除、拉人、新建 Bot）渲染到 `document.body`，不受右侧栏位置影响。这类桌面弹窗以宽度作为最低高度，并根据视口高度收窄，内容过长时在弹窗内滚动。
- 布局模式由宽度决定（`layout-mode.ts`：`wide`、`medium`、`compact`、`mobile`）：宽屏三栏，中屏浮动列表，桌面窄窗保持桌面布局，手机单屏加底部 dock（标签和输入框在同一个容器）。手机必须是真正的手机布局，不是缩小的桌面。
- 登录页和落地页的最底层背景是 `ui/components` 的 `AmbientField`：浅色主题是窗光，深色是星轨，两者是 beste-ui 的 WebGL 着色器原样拷贝（MIT，在 `ambient/vendor/` 里，带 `LICENSE` 和 `SOURCE`），不进文件长度和格式检查。页面色按 `--ambient-veil` 盖在上面，浅色 0.9、深色 0.55。
- 手机聊天输入区空白时为单行，麦克风切换到按住说话，松开发送可播放的短语音。桌面麦克风实时听写到可编辑草稿。交互约定见 [聊天语音输入](contracts/voice-input.md)。
- 「会议录音」点击即开始，应用外框的胶囊显示音量、时长、暂停/继续与停止。录音发起时绑定负责的 Bot 会话，全局入口默认使用主 Bot。胶囊可随输入区、底栏或底部安全区定位，正常停止后消失。录音自动提交转写，结果在该 Bot 的事项详情中查看。
- 浏览器会议录音由 `apps/web/src/lib/browser-meeting-recorder.ts` 持有，与站内页面无关。安全上下文使用 MediaRecorder 采集，录制时分段写入 PCM16 WAV，音频与索引一并保存到 IndexedDB。关闭文档、系统挂起或失去麦克风可能中断录音，重开恢复已持久化的片段。正常结束的录音在浏览器或手机 WebView 可运行时自动提交，已确认的音频段可跳过。桌面原生上传由持久队列负责。

- 扫一扫仅在移动宿主（含桌面 UA 的 iPad）显示，消息菜单及添加联系人页共用同一判断；桌面原生和电脑网页不请求扫码相机权限，仍展示自己的二维码供手机扫描。二维码组件的本地图片识别不受相机开关影响。

## 数据和缓存

- 服务端数据都经 `packages/ui/data` 的 hooks 读写，页面不直接调 `api-client`。
- 查询缓存持久化，`CACHE_VERSION` 变了就整体失效。草稿、未发送附件和发件箱存在 IndexedDB（`chat-cache`），重启不丢。
- 额度配置按版本缓存：服务端版本变了才重新拉，用户每次看额度不额外请求配置。客户端不写任何额度数字或价格。
- 实时事件走 `/v1/realtime` WebSocket，事件名和载荷在 `packages/protocol/src/realtime`。
- 来访会话可把一条已发送的文本转给主人。来访卡在主人主 Bot 会话和事项详情可处理，访客收到独立的结果消息。获准回复按原文展示。
- 对外资料与草稿按账号读取，单个 Bot 的对外人格按 Bot ID 读取。消息渠道管理页与聊天侧栏复用接入组件，授权链接仅保存在组件内存。
- 每次打开名片先重新验证可见性，名片查询排除在持久化快照之外。群管理返回的会话按版本合并到列表缓存。
- 失败一律显示真实原因（红色错误），不写成 Bot 的话。

## 联系人与好友申请

- 桌面 rail 提供独立「联系人」入口；手机只在消息加号菜单提供入口，不增加底部 tab。两处复用联系人列表与好友申请卡。
- 新增联系人走 `/v1/friend-requests`，既有联系人仍用 `/v1/contacts` 打开会话。申请单独保存 `pending/accepted` 与版本，通知消息只引用 `friendRequestId`；卡片读取共享请求查询，不从当前联系人关系推导历史状态。
- `friend_request.updated` 更新所有视图的申请缓存；重连重新取请求，旧版本事件不回退已同意状态。接受后联系人和会话查询刷新。
- `kind=system` 的会话显示为「系统通知」，无输入框、文件投放或群管理入口。只有真实服务端会话会出现在列表，不创建占位通知。
- 小程序联系人申请列表与系统通知复用动态申请卡；按账户隔离的版本化请求缓存合并 HTTP、WebSocket 和同意结果，旧快照不回退历史状态，重连重新取请求。

桌面更新包就绪时在侧栏设置上方显示强调色圆形入口，复用关于页 updater。两个重启入口都需确认录音、上传和本地执行可能中断，本地操作可能已生效但未回执；不自动结束、重试任务，也不承诺重启恢复。
