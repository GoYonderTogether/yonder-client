# Yonder 客户端架构

本文件描述公开客户端仓库**当前代码**的形状和强制规则；代码变了就改这里。2026-11-18 按 main 核对过一次。

- 产品原则和设计稿由维护者单独管理；本文记录公开客户端的实现与分层约束。

## 两个仓库

| 仓库                                     | 内容                                                                             |
| ---------------------------------------- | -------------------------------------------------------------------------------- |
| `yonder-client`（本仓库，公开，GPL-3.0） | Web、macOS、Windows、iOS、Android 壳，微信小程序，协议类型，API 调用层，全部界面 |
| `yonder`（私有）                         | 云端 API、账号、聊天、额度、模型适配与计费、技能正文、数据库、部署               |

本仓库不放生产密钥、数据库地址、模型价格数值、平台供应商的地址或类别。
`packages/protocol` 和 `packages/api-client` 在两个仓库各有一份，必须保持一致，**以本仓库为准**；
改协议时两边同时改。默认服务端是 `https://yonder.zethai.cn`，自建只在构建时用 `VITE_API_BASE`。

## 分层

```
apps/web            装配：providers、路由、页面、输入框、预览、本机能力桥
  packages/ui/features/{auth, me, members, landing, legal, meetings}
  packages/ui/data          TanStack Query、实时连接、本地存储、偏好
  packages/ui/shell         三层导航、布局模式、手势
  packages/ui/components    原子组件
  packages/ui/tokens        设计变量（packages/ui/i18n 与它并列）
  packages/ui/auth-presentation   登录页表现层，Web 和小程序共用
  packages/ui/chat-presentation   聊天/附件/输入区表现与正文解析，Web 和小程序共用
  packages/ui/chat-model          无 React/CSS 的消息合并、连续发送者分组规则

packages/api-client ─▶ packages/protocol（不依赖任何包）
```

- 上层只能依赖下层；feature 之间互不依赖。每个包能依赖谁写在
  `tools/check-dependency-direction.mjs` 的 `LAYERS` 表里，新包必须先登记。
- 包只能从入口导入（`tools/check-entry-imports.mjs`）。
- 单文件 300 行警告、500 行失败（`tools/check-file-length.mjs`）。
- 文案必须同时有 `zh-CN` 和 `en`；颜色、尺寸、圆角只用 tokens；图标用 `lucide-react`。用哪个 token 和组件见 `docs/design-system.md`；`tools/check-ui-raw-values.mjs` 按基线拦新增原始值，`tools/check-tailwind-sources.mjs` 保证每个 UI 包都被 Tailwind 扫到。
- `ui/data` 与小程序消息状态都引用 `chat-model` 的纯规则；`ui/components` 与小程序头像也复用其中的首字、稳定配色和 BotFace 路径数据。数据层不为合并消息导入展示 CSS 或另一版本的 React。`chat-presentation` 兼容 React 18/19，DOM 与 Taro 分别提供元素和原生事件适配。

| feature            | 内容                                                                                                              |
| ------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `auth`             | 登录、找回密码                                                                                                    |
| `me`               | 「我」的各个分区：账号与注销、隐私入口、Bot、额度与用量、模型、技能、设备、连接器、邀请、通用、关于；额度不足横幅 |
| `members`          | Bot 表单（新建和修改共用）、Bot 列表和详情、成员资料（真人和 Bot 同一套）、群资料和群管理、隐私三开关             |
| `meetings`         | 录音笔记胶囊                                                                                                      |
| `landing`、`legal` | 落地页、协议和隐私                                                                                                |

- 消息气泡不展示工具活动摘要；Web/桌面与小程序只从该消息的 `run.activity` 提取真实来源，按需显示独立“来源”入口，无来源不渲染。后端运行记录与其他卡片不受影响，小程序来源链接沿用点击复制方式。

## 应用和壳

| 目录                       | 内容                                                                                                                                                                                                                         |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/web`                 | 唯一的页面实现。`src/app/` 是外框、弹层和输入框（草稿、补全、语音、录音、附件、拖放），`src/pages/` 是各页面，`src/preview/` 是 PDF、docx、图片预览，`src/lib/` 是平台和本机能力的适配，`src/updates/` 是桌面和 Android 更新 |
| `apps/desktop`             | Tauri 2 壳，同一份 `apps/web` 构建产物。`src-tauri/` 里有本机文件连接器（`local_files*.rs`）、联系人独立窗口、Android 更新；`tauri.ios.conf.json` / `tauri.android.conf.json` 是手机壳                                       |
| `apps/miniprogram`         | Taro 小程序，独立依赖和 lockfile，不在 npm workspaces 里；登录复用 `auth-presentation`，聊天复用 `chat-presentation` 与 `chat-model`，键盘/滚动/文件与预览由宿主适配                                                         |
| `plugins/meeting-recorder` | 录音笔记 Tauri 插件（Rust 桌面采集、iOS、Android），4 秒分段 WAV、异常恢复；桌面原生持久上传队列不依赖 WebView，手机在 WebView 可运行时自动提交；界面在 `features/meetings`                                                  |

### 桌面托盘

macOS / Windows 的托盘面板是固定尺寸的独立 Webview，不启动主窗口的数据层或会话。面板收到仅含刷新信号的本地 DOM 事件后，再通过原生按窗口标签授权的命令读取当前快照。主窗口仅发布已发送到本机执行的连接器命令；凭后端发来的会话和 Bot ID 与已认证的本地会话缓存精确匹配，未匹配时只显示本机任务状态不可归属，不猜测当前对话，也不并入云端任务。结束、取消、断线或换账号时不保留旧任务。

## 界面模型

- 手机标签依次为主 Bot、消息、任务、记忆，主 Bot 直接打开原有主会话，是标签根页面而不是推进页：标签栏、消息列表的主 Bot 行和主 Bot 的通知都切到这个标签，标签根页面之间互相替换，主 Bot 始终垫在最底下，所以系统返回从其他标签根页面回到主 Bot，在主 Bot 上退出应用（`use-phone-tabs.ts`）。从主 Bot 推进的页面返回主 Bot；再点当前标签回到列表顶部或最新消息。登录后各端默认进入主 Bot。标签使用 Bot 全名或主人选中的昵称。手机主 Bot 页左上角和其他标签根页面一样是账号头像，进入账号设置，点击中间的 Bot 头像进入 Bot 详情。桌面竖栏的账号头像、消息、任务和记忆沿同一中轴排列。手机列表的账号头像和桌面竖栏的账号头像、底部设置按钮打开同一分组设置（`/me/:section`）。桌面宽窗（1024 CSS px 起）使用居中设置弹窗，点击外侧可关闭。桌面窄窗和手机使用从左侧滑入的整页设置，逐级返回原页面。
- 「我的 Bot」从 `/me/bots` 进入列表，单个 Bot 的概览、基本资料和对外人格各有页面。消息渠道与对外接待共用横向可滚动的 Bot 选择器，显示头像、名称和主人设置的职责备注。选择消息渠道的 Bot 会切换当前查看对象。从 Bot 详情进入 `/me/channels?bot=…` 时预选该 Bot，返回时回到原详情。连接设置和外部会话分别占一页，外部会话路径为 `/me/channels/external?bot=…`。
- `/me/reception` 顶部可直接指定账号的接待 Bot，下方是账号共用的对外资料库。资料可放在根目录或一层自建文件夹。草稿在「待审核草稿」里先阅读，批准时可选择保存位置。宽窗可同时浏览目录和正文，窄窗逐页进入。
- 层级从下到上：列表、内容（detail）、右侧栏（`ui/shell` 的 `SideLayers`，由 `AppShell` 的 `side` 统一管理）、弹窗（`Overlay`）。返回、Esc、滑动退出走同一个出口，按这个顺序一层层退：先退右侧栏里叠上去的页，再关右侧栏，再回到列表。手机和电脑是同一套顺序。
- 群聊和普通私聊从顶栏右侧「聊天设置」进入群资料、自己的 Bot 详情或对方的名片。手机主 Bot 页的入口集中在中间头像。Bot 详情与「我的 Bot」共用概览、基本资料和对外人格。直聊 Bot 侧栏为同一会话地址记录浏览器历史，浏览器返回逐层退出。群资料与名片的侧栏子页通过 `useSidePanel().push` 入栈。桌面右上角关闭整栏，也可点栏外空白处关闭。移动端从右侧滑入覆盖聊天，左上角用返回箭头回到上一级。切换会话、标签或页面时右侧栏关闭。
- 消息旁的发言者头像可点，打开对方名片（自己的 Bot 打开 Bot 详情），和顶栏入口一样走右侧栏；不做浮窗。真人名片列出 TA 的 Bot，接待 Bot 在前，点开是该 Bot 的名片。
- 自有 Bot 私聊的设置侧栏提供「重启 Bot」和「清空历史聊天」。重启直接重置当前会话上下文，并保留可见聊天记录。清空历史需要确认，确认后隐藏账号侧的旧消息并重置该会话上下文。
- 「记忆 › 了解」顶部是「我的名片」：二维码编完整地址 `/@对外号?i=邀请码`，手机相机和微信扫出即可打开，自家扫一扫只取路径；未登录打开时把邀请码存下，注册时算作分享人邀请。加好友页的「我的二维码」编同一地址。
- 真人私聊和群聊的顶栏左对齐显示名称，消息保留左右头像，群聊还显示发言者名字。Bot 私聊在聊天区上方居中显示头像和名字。正文流式发出时，名字下显示「正在输入」。其余时间有该 Bot 负责运行的子任务时，显示「正在处理」和任务名。状态最多显示两行，超长用省略号。只有双方参与时省去消息头像。
- 主 Bot 会话的头像、名字和状态浮在聊天区上方，消息可从这些控件的局部磨砂后方经过。电脑和手机网页从聊天区顶边向下渐隐。原生手机沿用系统安全区与状态栏渐隐。手机左上角的账号头像打开账号设置，电脑右上角的「聊天设置」打开 Bot 详情。进入已有历史的会话时定位到最近消息。
- 手机键盘：iOS 宿主在键盘开始移动时把最终高度和时长发给页面（`apple/KeyboardFollow.mm` 的 `yonder-keyboard` 事件），外框用同一时长和曲线（`--ease-keyboard`）缩放，底部容器贴着键盘上沿一起升起，键盘弹起期间文档不被系统上推。浏览器没有这个事件，仍按 `visualViewport` 跟随。键盘弹起时标签栏和 Home 条留白收起，输入框保留；往下拖或点消息区空白处收起键盘。
- 触感反馈：页面只调 `lib/haptics.ts` 的 `haptic()`，外壳通过 `setShellHaptics` 接入。切换标签和右滑返回越过返回点用选择反馈，点开输入框用轻碰撞，开始按住说话用中碰撞，录音上滑越过取消线用选择反馈，发送失败用失败反馈；再点当前标签和发送成功不震。只有 iOS、Android 应用有反馈，系统关闭触感时自动静音，网页不震。按钮在手指按下时就变化，不等松手。
- 手机「我」从左侧进入，所以向左关闭：根页面左上角不放返回箭头，右上角放圆形底的关闭叉（`AppShell` 通过 `ShellChrome.right` 给 `ListFrame`）。从「我」推进的子页面仍是左上角返回。「我」是表单页，顶栏是不透明的普通栏，不做渐变模糊，不盖住第一个表单项（`native-mobile.css` 的 `[data-me-layers]`）。顶部资料块是名片（`me-card.tsx`），与记忆页对外名片同一比例和底色，整张可点进编辑资料，简介是别人看到的那一句。
- 滑动关闭的松手判定（`navigation/release.ts`）：手指按着时层与手指 1:1，不加缓动。松手只看当下：停住超过 50 毫秒视为静止，拖过宽度的 1/4（最少 64 px）就关闭，不需要甩；甩动速度达到每秒 300 px 时只需 16 px；手指正往回收时保持打开。关闭时从手指放开的位置接着走，不先弹回。越过关闭距离时有一下选择触感。
- 群资料在群名左侧显示成员组合头像，按权限在页面底部显示「解散群聊」或「退出群聊」。「Bot 设置」是群资料的子页，管理本群的 Bot 回复付费方式。添加成员在桌面是居中弹窗，在手机进入侧栏栈的子页。选人默认可浏览最近聊过的可添加联系人和全部可添加联系人，输入关键词可以筛选。
- 确认、填写类弹窗（确认删除、拉人、新建 Bot）渲染到 `document.body`，不受右侧栏位置影响。这类桌面弹窗以宽度作为最低高度，并根据视口高度收窄，内容过长时在弹窗内滚动。带操作区的弹窗将按钮排在底部，正文过长时单独滚动。
- 浮层的遮罩在关闭那一刻立即移除，面板继续播放退出动画；变暗的页面不会比触发关闭的操作多停留一会儿。
- 布局模式由宽度决定（`layout-mode.ts`：`wide`、`medium`、`compact`、`mobile`）：宽屏三栏，中屏浮动列表，桌面窄窗保持桌面布局，手机单屏加底部 dock（标签和输入框在同一个容器）。手机必须是真正的手机布局，不是缩小的桌面。
- 登录页和落地页的最底层背景是 `ui/components` 的 `AmbientField`：浅色主题是窗光，深色是星轨，两者是 beste-ui 的 WebGL 着色器原样拷贝（MIT，在 `ambient/vendor/` 里，带 `LICENSE` 和 `SOURCE`），不进文件长度和格式检查。页面色按 `--ambient-veil` 盖在上面，浅色 0.9、深色 0.55。
- 手机聊天输入区空白时为单行，麦克风切换到按住说话，松开发送可播放的短语音。桌面麦克风实时听写到可编辑草稿。交互约定见 [聊天语音输入](contracts/voice-input.md)。
- Bot 输入框和消息列表的「+」各提供一个「录音笔记」入口，点击即开始。应用外框的胶囊显示音量、时长、暂停/继续与停止。录音发起时绑定负责的 Bot 会话，全局入口默认使用主 Bot。正常停止后自动提交转写，后台默认区分发言人，结果在该 Bot 的事项详情中查看。
- 浏览器录音笔记由 `apps/web/src/lib/browser-meeting-recorder.ts` 持有，与站内页面无关。安全上下文使用 MediaRecorder 采集，录制时分段写入 PCM16 WAV，音频与索引一并保存到 IndexedDB。关闭文档、系统挂起或失去麦克风可能中断录音，重开恢复已持久化的片段。正常结束的录音在浏览器或手机 WebView 可运行时自动提交，已确认的音频段可跳过。桌面原生上传由持久队列负责。

- 扫一扫仅在移动宿主（含桌面 UA 的 iPad）显示，消息菜单及添加联系人页共用同一判断；桌面原生和电脑网页不请求扫码相机权限，仍展示自己的二维码供手机扫描。二维码组件的本地图片识别不受相机开关影响。

### 页面

桌面消息、任务、记忆列表的页名与创建入口同排。手机消息列表左上角显示用户头像和用户名，任务和记忆列表保留左上角头像并居中显示页名。手机主 Bot 页左上角的账号头像进入个人设置，Bot 头像进入该 Bot 的设置。任务和记忆的分段筛选位于第二行，桌面与手机共用胶囊样式。

任务页右上角的加号在「事项」和「目标」下是同一个菜单：新建事项、新建目标、新建定时任务，切换分段只换下面的列表，不换加号的职责。新建定时任务在手机上打开主 Bot 抽屉，在电脑上从「事项」进入时先切到「目标」再展开表单。

桌面导航栏的「联系人」进入 `/contacts`，使用与消息、任务、记忆相同的列表框架和选中样式。联系人行打开 `/@ID` 名片，返回恢复联系人列表。手机从消息列表的「+」菜单打开联系人。

## 数据和缓存

- 服务端数据都经 `packages/ui/data` 的 hooks 读写，页面不直接调 `api-client`。
- 聊天输入区不提供停止 Bot 回复的操作；发送失败和回复失败仍可重试。
- 查询缓存持久化，`CACHE_VERSION` 变了就整体失效。草稿、未发送附件和发件箱存在 IndexedDB（`chat-cache`），重启不丢。
- 额度配置按版本缓存：服务端版本变了才重新拉，用户每次看额度不额外请求配置。客户端不写任何额度数字或价格。
- 实时事件走 `/v1/realtime` WebSocket，事件名和载荷在 `packages/protocol/src/realtime`。
- 连接器授权卡由服务端推进状态：任意端在卡片上点「允许」即同意，服务端选设备并推 `connector.grant.request`；目标设备的桌面客户端直接写本地授权库（不再弹 Yonder 自己的确认框，系统自己的权限框照常出现），随后上报 `connector.ready`。`connector_request.updated` 把整张卡写入 `["connector-request", id]` 缓存，所有端随之更新。没有 `sessionStorage` 接力，也没有把用户原话重发一遍。
- 设备授权与任务续跑分别显示状态。服务端根据授权卡记录在原 Bot 会话排队，临时排队失败由服务端恢复；最终失败时卡片提供「继续任务」，沿用已生效的授权。已启动的运行按现有 Bot 运行状态展示。
- 来访会话可把一条已发送的文本转给主人。来访卡在主人主 Bot 会话和事项详情可处理，访客收到独立的结果消息。获准回复按原文展示。
- 对外资料与草稿按账号读取，单个 Bot 的对外人格按 Bot ID 读取。消息渠道管理页与聊天侧栏复用接入组件，授权链接仅保存在组件内存。
- 每次打开名片先重新验证可见性，名片查询排除在持久化快照之外。群管理返回的会话按版本合并到列表缓存。
- 失败用对应的产品状态说明原因。应用级临时反馈由 `apps/web` 根层统一展示，后台重试过程保持静默。需要用户处理的失败在相关操作旁显示恢复入口，整页加载失败由页面错误状态处理。

## 联系人与好友申请

- 桌面 rail 提供独立「联系人」入口；手机只在消息加号菜单提供入口，不增加底部 tab。两处复用联系人列表与好友申请卡。
- 新增联系人走 `/v1/friend-requests`，既有联系人仍用 `/v1/contacts` 打开会话。申请单独保存 `pending/accepted` 与版本，通知消息只引用 `friendRequestId`；卡片读取共享请求查询，不从当前联系人关系推导历史状态。
- `friend_request.updated` 更新所有视图的申请缓存；重连重新取请求，旧版本事件不回退已同意状态。接受后联系人和会话查询刷新。
- `kind=system` 的会话显示为「系统通知」，无输入框、文件投放或群管理入口。只有真实服务端会话会出现在列表，不创建占位通知。
- 小程序联系人申请列表与系统通知复用动态申请卡；按账户隔离的版本化请求缓存合并 HTTP、WebSocket 和同意结果，旧快照不回退历史状态，重连重新取请求。

桌面侧栏设置上方的更新入口保留 44px 点击区与 32px 圆形视觉：下载时白底蓝字显示百分比和外圈进度，未知大小只显示等待指示；下载包就绪后才成为强调色可点击入口，复用关于页 updater。侧栏与关于页的重启入口都使用应用内确认弹窗，提醒录音、上传和本地执行可能中断，本地操作可能已生效但未回执；取消不安装，安装失败保留错误与重试入口，不自动结束、重试任务，也不承诺重启恢复。
