# 聊天语音输入

桌面听写交互于 2026-11-15 确认，手机按住说话交互于 2026-11-19 补充。

## 手机按住说话

- 聊天输入区空白时保持单行。右侧的麦克风切入语音模式，键盘图标切回文字。文字或附件就绪后可发送，有进行中的发送或回复时仍提供相应的停止操作。
- 在语音模式按住说话，松开后自动发送本次录音。发给 Bot 或联系人时，消息统一显示为带时长的语音条，点按原地播放或暂停。会话列表显示「语音消息」。Bot 会话里的识别文字供 Bot 理解，消息区呈现语音条。手动上传的音频使用普通附件入口。
- 采音开始后，聊天页面覆上一层微冷的暗色蒙版。淡蓝色光晕的圆心位于屏幕下方，屏内只露出一道平缓的弧，边缘泛冷亮光。身后的聊天内容越靠近底部中央越模糊，「松手发送，上滑取消」保持清晰。向上滑过判定距离后，光晕主体切为淡红，文案变为「松手取消」。滑回时恢复蓝光并继续本次录音，松手时立即收起效果，按当前状态发送或取消。轻微移动与横移保持发送状态。
- 失去触控、切会话或中断采音时取消未完成的按压并收起提示。会议录音占用麦克风时，短语音暂停使用。

## 桌面实时听写

- 保留现有输入框。开始听写时保存光标或选区，从该位置插入；选区在第一段非空结果到来前不删除。
- 录音期间仅把麦克风图标变成可点击的方形终止图标，不增加状态栏、计时、波形。无障碍名称和必要的失败反馈保留。
- 点击终止代表停止本次采音、完成尾句并保留文字，不引入断点续录。
- 光标移动、选择、键盘编辑、粘贴、删除及输入法编辑立即打断听写，保留已显示文字。程序自身更新光标不算用户打断；滚动和鼠标移动不打断。
- 点击发送立即停止采音。从此次点击起最多等待 2000ms：识别先完成就发送，到期则冻结并发送已显示文字。此上限约束等待识别，不保证网络送达时延。
- 等待发送期间继续编辑，取消待发送动作。新一轮听写、会话切换和页面退出均使旧回调失效。
- 发送只触发一次，迟到结果不能补发、修改已发送消息或重新写入草稿。
- 没有文字且没有附件时不发空消息；发送失败保留草稿，后续输入不被旧发送清空。

## 实现边界

- 语音会话负责采音、上游连接、分句结果和资源释放；编辑器负责本次听写范围；发送协调复用现有草稿与消息幂等机制。
- 阿里云凭据仅保存在服务端，客户端通过 Yonder 的已鉴权接口接入。
- 临时结果替换同一句的旧文本，不重复追加；流式预览不逐帧写持久缓存。
- 正常停止接收尾句；编辑打断立即收回写权限，不能仅依赖断开连接来避免迟到结果。
- 权限迟到、断网、系统中断、切换会话和卸载都必须释放麦克风及连接。不自动重录、重放或切换付费服务。
- TTS 不属于本轮实现，不新增通用语音平台或富文本编辑器。

## 必须覆盖的验证

1. 句首、句中、句尾插入及选区替换；连续中间结果不重复。
2. 光标和输入法接管后，旧识别结果不能覆盖用户编辑。
3. 识别先完成与 2000ms 到期两条发送路径，以及同刻竞态、重复点击。
4. 等待期间编辑、切换会话、重新开始听写及迟到授权。
5. 空转写不空发、发送失败保留草稿、新输入不被旧发送清空。
6. 原生采音释放、真实 PCM 重采样、云端鉴权与上游正常收尾。
7. 两仓库规定检查；实际运行页面预览；真实供应商与各端采音证据分别记录。
